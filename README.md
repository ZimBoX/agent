# Claude Assistant — внутренний инструмент компании

Windows-приложение для сотрудников: правый клик по документу (или папке) в
Проводнике → отправить в Claude, получить анализ по шаблону или своему промпту.
Заточено под строительную/подрядную специфику (договоры, сметы, ТЗ, акты).

> **Свежая сессия Claude Code, начни отсюда.** Этот файл — карта проекта и
> текущее состояние. Детали: [PROJECT_PLAN.md](PROJECT_PLAN.md) (архитектура и
> принятые решения), [IMPLEMENTATION_CHECKLIST.md](IMPLEMENTATION_CHECKLIST.md)
> (подробная история реализации по этапам), [ЗАПУСК.md](ЗАПУСК.md) (как поднять
> локально), [ПЕРЕЕЗД.md](ПЕРЕЕЗД.md) (перенос на новую машину).

## Архитектура

Три компонента в одном репозитории + внешний агрегатор модели:

| Компонент | Папка | Стек | Роль |
|---|---|---|---|
| **Клиент** | `client/ClaudeAssistant.Client` | WinUI 3 (.NET 8, unpackaged) | Десктоп: окно запроса, чат-тред, трей, автообновление |
| **Shell-расширение** | `shell-extension/ClaudeAssistant.ShellExtension` | .NET 8 COM (`IExplorerCommand`) | Пункт «Отправить в Claude Assistant» в меню Проводника |
| **Тонкий установщик** | `client/ClaudeAssistant.Client.InstallerLauncher` | .NET 8 (trimmed single-file) | Качает Setup.exe с бэкенда, ставит с правами админа, регистрирует верхнее меню |
| **Бэкенд** | `backend/ClaudeAssistant.Api` | ASP.NET Core 8 + EF Core + Postgres | API, аутентификация устройств, шаблоны, история, вызовы модели, release-фид |

- **Модель** вызывается не напрямую у Anthropic, а через агрегатор **aitunnel**
  (`https://api.aitunnel.ru`) официальным Anthropic .NET SDK. Ключ — в переменной
  окружения `AITUNNEL_API_KEY` (в git/файлы **не** пишется).
- **Автообновление** клиента — Velopack (`vpk`). Бэкенд раздаёт release-фид из
  `/releases`. Два канала: `beta` и `win` (релиз).
- **Верхний уровень контекстного меню Windows 11** — sparse MSIX-пакет
  (`client/ClaudeAssistant.Client/msix-sparse`), подписанный самоподписанным
  сертификатом (`certs/`, **не в git**), объявляющий packaged-COM для того же CLSID.

## Как это работает (поток запроса)

1. Пользователь: ПКМ по файлу/папке → «Отправить в Claude Assistant» (верхний
   уровень меню или «Показать доп. параметры») ИЛИ открывает клиент из трея.
2. Клиент шлёт на бэкенд шаблон/свой промпт + прикреплённые файлы и/или путь
   папки-объекта (сетевые диски конвертируются в UNC, см. `NetworkPathResolver`).
3. Бэкенд (`ChatCompletionService`) гоняет agentic-цикл: модель через инструменты
   `list_files`/`read_document` сама читает документы в папке-объекте (с
   пагинацией по большим файлам) и `web_search` ищет в интернете при необходимости.
4. Пока идёт обработка — живой статус пользователю по SignalR («Думаю…»,
   «Читаю: договор.pdf»).
5. Ответ показывается чат-тредом; диалог можно **продолжить** (follow-up) в
   течение 1 часа — контекст (включая прочитанные документы) переиспользуется из
   prompt-кэша Anthropic за ~1/10 цены.

## Текущее состояние

Основной функционал готов и работает; идёт полировка перед деплоем на боевой
сервер компании (Этап 12 в PROJECT_PLAN — ещё не сделан).

Реализовано (последние сессии, поверх базового функционала из чеклиста):
- Продолжение диалога с prompt-кэшем (1 ч), чат-тред с пузырями, Enter-отправка,
  осмысленные заголовки истории, сохранение диалога в БД.
- Пагинация чтения больших документов (`read_document` с `offset`).
- Нативный веб-поиск Anthropic (`web_search`, доступен везде, лимит 3/запрос).
- Живой статус обработки по SignalR + щедрые таймауты (15 мин).
- Тонкий скачивающий установщик; верхний уровень меню Windows 11 (sparse MSIX);
  динамическая высота окна; иконка приложения.
- Конвертация путей сетевых дисков (X:\) в UNC для доступа бэкенда.

Открытые/на будущее:
- **Этап 12** — деплой на on-prem сервер (Ubuntu + Docker), конфигурируемый
  адрес сервера в клиенте, сертификат для внутреннего адреса.
- Гранулярный статус веб-поиска потребовал бы streaming-режима ответа.
- Текущий рабочий канал сборок — `beta`. Последняя собранная версия — см.
  `releases-local-beta/` и админку `/admin/releases`.

## Секреты и то, чего нет в git (критично для переезда)

- `AITUNNEL_API_KEY` — ключ агрегатора, только в переменной окружения.
- `certs/ClaudeAssistant.pfx` + `.cer` — сертификат подписи MSIX (gitignored).
  **Обязательно сохранить при переезде** — иначе верхнее меню придётся
  пересоздавать с новым сертификатом. Пароль pfx — у владельца проекта.
- Данные Postgres — в docker volume `postgres_data` (тестовые, пересоздаваемы).

Подробности переноса — [ПЕРЕЕЗД.md](ПЕРЕЕЗД.md).

## Запуск (кратко)

1. Docker Desktop → `docker compose up -d` (Postgres).
2. `$env:AITUNNEL_API_KEY="..."; dotnet run --project backend\ClaudeAssistant.Api --launch-profile http`
3. Клиент — установить `Install ClaudeAssistant.exe` (тонкий установщик).

Полностью и с диагностикой — [ЗАПУСК.md](ЗАПУСК.md).

## Сборка релиза (шпаргалка)

Пересобрать клиент (VS MSBuild, не `dotnet` — из-за бага генерации `.pri`) →
свериться с `.pri` в `publish\` → собрать payload `ShellExtension\` → `vpk pack`
`--channel beta` → залить на бэкенд (`/api/admin/releases/upload`, зип с nupkg +
RELEASES + json + Setup.exe) → отозвать старые версии. Детали и грабли — в
IMPLEMENTATION_CHECKLIST.md (искать «vpk pack», «.pri», «mt.exe»).
