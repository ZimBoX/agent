# Перенос проекта на новую машину

Код весь в git и запушен на GitHub (`origin` = `https://github.com/ZimBoX/agent.git`).
Но часть нужного **не в git** и потеряется при переустановке Windows — это надо
сохранить ОТДЕЛЬНО заранее.

## 1. ПЕРЕД переустановкой — сохранить вне машины (USB/облако)

- [ ] **`certs/` целиком** (`ClaudeAssistant.pfx` + `ClaudeAssistant.cer`) —
      сертификат подписи MSIX. Без него верхний уровень меню Windows 11 придётся
      пересоздавать новым сертификатом (сменится издатель, старые установки
      перестанут обновлять пакет). Пароль от `.pfx` — записать отдельно.
- [ ] **`AITUNNEL_API_KEY`** — ключ агрегатора (у владельца уже есть). Без него
      бэкенд не вызовет модель.
- [ ] Убедиться, что всё закоммичено и **запушено**: `git status` чисто,
      `git push`. (Данные Postgres — тестовые, сохранять не нужно.)

## 2. На новой машине — поставить

- **.NET 8 SDK** (обязательно 8.x — проект на `net8.0`).
- **Visual Studio 2022 Build Tools** с workload «.NET Desktop» — нужен именно
  `MSBuild.exe` из VS, а не `dotnet build`: у `dotnet` баг генерации `.pri` для
  WinUI 3 (см. память проекта и IMPLEMENTATION_CHECKLIST). Путь MSBuild в скриптах
  сессии: `...\Microsoft Visual Studio\<ver>\...\MSBuild\Current\Bin\amd64\MSBuild.exe`.
- **Windows App SDK** (для WinUI 3 клиента) — обычно подтягивается NuGet-ом при
  restore, но рантайм может понадобиться отдельно.
- **Docker Desktop** — для Postgres.
- **Windows SDK** (для `makeappx.exe`/`signtool.exe`/`mt.exe` при пересборке MSIX).

## 3. Развернуть проект

```powershell
git clone https://github.com/ZimBoX/agent.git
cd agent
# восстановить сохранённое:
#   - положить обратно папку certs\ (pfx + cer)
docker compose up -d                     # Postgres
$env:AITUNNEL_API_KEY = "sk-aitunnel-..."
dotnet run --project backend\ClaudeAssistant.Api --launch-profile http
```

БД пустая — миграции EF Core применятся сами при старте (или создать через
`dotnet ef database update`, если настроено). Первого сотрудника/устройство
завести через админку `/admin` (логин `admin`/`admin` по умолчанию).

## 4. Проверить

- Бэкенд слушает `http://localhost:5149`, `/admin` открывается.
- Собрать и поставить клиент (тонкий установщик), проверить основной поток.
- Веб-поиск: агрегатор поддерживает нативный `web_search` — проверялось live,
  ключ тот же.

## Что важно помнить (грабли, задокументированы подробно в чеклисте)

- Сборка клиента — только через **VS MSBuild**, и каждый раз сверять `.pri` в
  `publish\` (баг: не копируется автоматически).
- Бэкенд отвечает 500 на всё → почти всегда **Docker/Postgres не поднят**.
- Сетевые диски (X:, Y:) видны только в сессии пользователя — клиент шлёт пути в
  UNC (`NetworkPathResolver`), бэкенд запускать под тем же пользователем.
- Машина, на которой велась разработка, была нестабильна (частые BSOD) — это
  было железо/ОС, не проект.
